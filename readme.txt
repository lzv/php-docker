Пример каркаса окружения для разработки на PHP с Docker. 

PHP приложение находится в подкаталоге app (не включено). Предполагается, что публичные файлы приложения находятся в подкаталоге app/public_html, а код приложения - в app/private.

Для изменения набора пакетов composer используется скрипт run_composer.sh. Не нужно, чтобы composer был установлен на хосте. Скрипт меняет только файлы composer.json и composer.lock, после чего образ с приложением пересобирается и пакеты скачиваются внутри контейнера.

Для запуска контейнеров нужно выполнить:
docker compose -f compose-dev.yaml up -d

Для запуска с синхронизацией кода и пересборкой при изменении composer.lock:
docker compose -f compose-dev.yaml watch

Файл compose-prod.yaml - пример запуска для продакшена (дополнительно настройте для себя).

При использовании compose-dev.yaml запускаются сервисы: 

1). proxy - traefik.

Принимает все входящие запросы по порту 8080. На продакшене по порту 80.
По td.localhost:8080 доступен его Dashboard. На продакшене Dashboard отключен.
По localhost:8080 - основное приложение PHP. На продакшене нужно заменить localhost на адрес сайта.
По db.localhost:8080 - phpmyadmin. На продакшене нужно заменить localhost на адрес сайта или настроить другой домен.

2). server - собранный образ с приложением PHP.

Монтируется каталог emails, куда будут приходить письма, отправленные во время разработки. Настройте ему права 777, чтобы процесс в контейнере мог записать туда файлы. Также можно: при сборке контейнера создать пользователя с вашим UID и запускать процесс от него (вместо www-data); настроить user namespaces для демона Docker.
На продакшене письма отправляются как обычно.

3). db - mysql:8. 

В каталоге dbdata будет хранится база данных. На продакшене вместо этого используется именованый том.

В dev конфигурации используется секрет с паролем root БД. На продакшене вместо этого генерируется случайный пароль root БД, и его нужно прочитать из лога. 

4). phpmyadmin.

Сразу заходит под пользователем root. На продакшене вместо этого запрашивается логин и пароль.

-----

Xdebug может не подключаться к IDE. При использовании на системах с файерволом, например ufw в Ubuntu, нужно выяснить, какой ip у Gateway в сети docker, и разрешить подключения от него, например так:
sudo ufw allow from 172.18.0.0/16 to any port 9003 comment 'docker xdebug'

Выяснить нужный ip можно так:
docker inspect id_контейнера | grep Gateway
